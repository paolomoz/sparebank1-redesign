# Archetype brief — Flow B prototypes (read fully before touching anything)

You are rendering ONE or more archetype prototypes of the SpareBank 1 redesign. The canon author (market landing `nb-bank-privat-html`) is approved; its chrome and CSS are the canon. You own only your slugs' files. Never edit `stardust/scripts/proto/chrome.mjs`, `build.mjs`, `data.mjs`, `DESIGN*.{md,json}`, `direction.md`, `state.json`, `journal.md`, `status.jsonl`, or another slug's files — the lead merges. If canon genuinely lacks something you need site-wide, append a request to `stardust/prototypes/canon-requests.md` (create if absent) and solve locally in your page CSS with `data-deviation="<reason>"` on the affected element.

## Contract (every archetype)
1. **Content verbatim.** Every heading, paragraph, list item, CTA label, href (with icid query strings), image src + alt, FAQ Q/A, table cell of the captured page appears in the prototype. Source: `stardust/current/pages/<slug>.html` (rendered DOM) — read it through `node stardust/scripts/page-content.mjs <slug>` (add `--hidden` to see collapsed panels/accordion bodies) and query it in your page module with linkedom selectors (see `stardust/scripts/proto/pages/nb-bank-privat-html.mjs`). Never retype copy by hand when a selector can lift it. Hidden accordion bodies, "Se flere" overflow items, tab panels: render them (closed `<details>`, or visible) — never drop. Gate: `node stardust/scripts/content-check.mjs <slug>` must PASS (0 missing). Legitimate exclusions only: chevron/decoration imgs, `href="#/"`, dynamic-picker UI strings (error/empty states) — if the checker flags something you believe is UI state, do not weaken the checker; note it in your shape brief § Unsourced/Excluded and tell the lead.
2. **Build path.** Write `stardust/scripts/proto/pages/<slug>.mjs` exporting `render({doc,pj,header,router,footer,slug})` → `{ template, title, description, main, css, provenance, router?:false, footer? }` and run `node stardust/scripts/proto/build.mjs <slug>` → `stardust/prototypes/<slug>-proposed.html`. Chrome (skip links, header, router band, footer, fonts, tokens, canon CSS, nav script) is injected by the builder from the captured page's own header/footer data — do not re-author it. Pages without a captured `.bank-choice` get no router automatically. `nettsider-frontend` pages (news, campaign, stories) carry their footer INSIDE `<main>` (`main > div.footer`) and a `main > div.header` article header: build `footer` yourself from that DOM shape or pass `footer:` data in the same shape `footerData()` returns (columns/small/address; no contact tabs) — see `data.mjs`.
3. **Shape brief first.** `stardust/prototypes/<slug>-shape.md` per `skills/prototype/reference/page-shape-brief.md` with the `_provenance` disciplines 1–5 (capturedSourceLineage, antiTemplatePass with ≥2 alternatives per captured pattern, surprise: low, substrateTransitions ≤2 exceptions, voiceClassification, signatureElements, unsourcedContent []). Use the market-landing brief as the model. Hands-off: the brief is its own record (no confirmation wait). Roll `"/Users/paolo/.claude/plugins/cache/impeccable/impeccable/4.3.1/skills/impeccable/scripts/impeccable" concept-seed --scope surface --mode <persuade|read|operate>` once per page, list 5–7 grounded structures ordered by resonance, build the dealt lead, record the key + indices in the brief.
4. **Design system = DESIGN.md (target), verbatim IA.** Same section sequence as captured; re-composed surface. Rules that bite: 1.25 type scale on the three brand faces (`.display`, `h1/h2/h3`, `.title-sm`, `.lead`, `.small`, `.label` classes exist); one action per module (`.btn-action` Skog only for log-in / become-customer / apply-type captured `ffe-button--action`; other captured primary/secondary buttons → `.btn-primary` / `.btn-secondary`; inline → `.btn-inline`); paper changes (`.paper-sand`, `.paper-frost`, `.paper-syrin`) mark movements — max 2 tinted movements per page, never the same tint adjacent; no `<hr>`, no shadows at rest, no eyebrow/kicker above a heading (captured category labels go under the title as `.meta`); photos as content: `<img class="photo">` (3:2, one-corner-pair mask, `height:auto`), `.photo-sm` for cards; first above-the-fold photo `loading="eager" fetchpriority="high"`, others lazy; spot illustrations `aria-hidden` `.illu`; FAQ → `.faq` with `<details>`/`<summary>` + `icons.down`; feedback strip → `.feedback` with `icons.thumbUp/thumbDown` buttons (dynamics #5 interim: `type="button"`); tips → `.callout` with `icons.bulb`; back-link → `.backlink` with `icons.back`. Prose max 68ch (`.prose`). Tabular numerals on prices (`.num`). Every `section` inside `<main>` carries `data-section`, `data-intent`, `data-layout` (+ `data-module`, `data-items`, `data-media` when relevant); `body[data-template]` is set from your `template`.
5. **Dynamics interim tiers** (`stardust/dynamic-features.md`): calculators → static shell of the captured widget's visible fields/labels/result strings with a `<p class="small muted">` note "Kalkulatoren kobles til når tjenesten er tilgjengelig" is NOT allowed (that is invented copy) — instead render the captured widget text verbatim, controls disabled (`disabled`), and record the interim in the brief; bank-choice CTAs with `href="#"` keep `#` (dynamics #2 dialog at rollout); feedback thumbs static; YouTube → `<iframe loading="lazy" title=…>` with the captured src, or a link when src is runtime-injected; listings (news/markedsnytt) render the captured cards.
6. **Validation loop until clean** (never mark done with P0/P1 outstanding): `node stardust/scripts/validate-prototype.mjs <slug>` (three viewports, console, network, overflow, landmarks, a11y quick-pass, contrast, LCP, interaction smoke, 360 nav audit; screenshots land in `stardust/validation/<slug>/`) and `node stardust/scripts/content-check.mjs <slug>`, then `"/Users/paolo/.claude/plugins/cache/impeccable/impeccable/4.3.1/skills/impeccable/scripts/impeccable" detect --json stardust/prototypes/<slug>-proposed.html > stardust/validation/<slug>/detect.json` (cramped-padding on `.movement`/`.footer-*`/`.hdr-utility` are known static-CSS misreads of `padding-block: var(--section-padding)` — record as dismissed; fix anything else real). Then LOOK at the three screenshots (Read tool) and judge brand-fit, hierarchy, calm vs generic, mobile composition; fix and re-run. Then spawn `impeccable:impeccable-finish-reviewer` once with the same packet shape the lead used (request, constraints incl. offline photo plates, artifact, 3 screenshots, shape brief, direction.md, DESIGN.md, PRODUCT.md, improvements list, captured screenshot `stardust/current/assets/screenshots/<slug>.png`, detect.json, report.json, craft-floor path); apply its material fixes in one batch, re-run the loop, and record its disposition + fixes in your brief's `## Review` section. Two review rounds max.
7. **Hand back** (do not edit state.json): append to `stardust/prototypes/<slug>-shape.md` a `## Validation` section with the final harness line, content-check line, detect summary, reviewer disposition, viewport heights, and the list of `data-deviation` elements (canon deviations) — the lead approves, extends canon and writes state.
